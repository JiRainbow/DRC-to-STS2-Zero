## 战斗渲染相关性
**结论：本卷不含颜色脉冲机制本体，但含 SpinePlugin 渲染批处理的上游与 BP 入口，位于地址域最尾部（与已知顶点色生产端同邻域）。**

专项核查结果（grep 全文件）：
1. **0x70b25f0 / 0x70b2424 / 0x70c0d30 本体不在本卷**：本卷地址上限 0x70b1554，三者均越界（依据：profile addr_max + FUNC 标记最大地址 0x70b1554）。但 0x70b2424/0x70b25f0 紧贴卷尾，属同一 SpinePlugin 代码邻域。
2. **谁调用 0x6e2b57c：本卷无任何调用者**。`grep "e2b57c"` 零命中（含数据表引用），UAzureSceneImage 的 exec thunk 不被本卷任何函数/表引用。
3. **AzureCharColor / SetAzureCharColor：零命中**；`pulse`：零命中（与 profile keywords pulse=0 一致）。0xa0e5800（UMID 参数族）与 0x9dbadd4 均远超本卷上限，不在卷内。

本卷内与战斗渲染相关的实证函数：
- **0x70b1554（size 2640）——spine attachment 分批编译（最有价值）**：逐 slot 取 attachment，vtable 与 &DAT_0c37e7c8/&DAT_0c37e758/&DAT_0c37e688 三个类型描述符比较（Region/Mesh/BoundingBox 三类 attachment），Region 按 4 顶点/6 索引累计、Mesh 按自身顶点/索引数累计，生成 0x28B 批次记录，**每批次默认颜色写入 FF FF FF FF（FColor 白）@+4**（L232583-232586、L232712-232715、L232851-232854 三处相同模式），并维护"上一个裁剪/遮挡批次"的插入排序（memmove）。这是卷外 0x70b25f0/0x70b2424 顶点色生产端的**直接上游分批阶段**——批次默认白 + slot 颜色相乘的流水线结构与此吻合；下游填色时批次内的白即"贴图原色"基调。调试模式（DAT_0c37da20>5）还会按 attachment 名做字符串排序（调卷外 FUN_070b20cc）。
- **0x6f385a0（size 232）——USpineWidget::SetNormalBlendMaterial BP thunk**：双重类型校验（USpineWidget、UMaterialInterface）后调 `FUN_070cd1ec`（实现体在卷外 0x70cd1ec）。这是 SpineWidget 换混合材质的蓝图入口之一，与"贴图原色↔纯黑"所需的材质切换机制相邻接；真实实现需到 0x70cd1ec 所在卷查。
- **卷尾 thunk 群 0x70a2cfc–0x70b0478（12 个 200–400B）+ 0x7017784/0x701be38/0x701e204/0x709b310/0x709d1cc**：Spine 各组件 BP 调用的校验/编组层，无颜色逻辑，仅证明本卷尾部是 SpinePlugin BP 面向蓝图的一层。
- **0x6c9fb74 `FQuadBuffer::AddBoxClipped`（size 5116）**：Slate UI 四边形顶点生成（带顶点色字段），属 UMG/UI 渲染顶点缓冲，**不是**角色顶点色 tint 链（依据：操作 FMargin/FBox2D/FSlateRect/ESlateBrushMirrorType，纯 Slate 绘制几何）。
- **Niagara 颜色数组 DI（0x68ef0f4 等 FNiagaraDataInterfaceArrayImpl<FLinearColor,UNiagaraDataInterfaceArrayColor> 族，L84379 起）**：粒子颜色数组数据接口，属特效而非角色 pulse。
- 未发现：Spine 顶点色填充、Dark 二级 tint、方向光替换链、Azure 角色颜色函数的任何本体或调用点——这些应到 0x70b1554 之后的卷（0x70b1554–0x70cxxxx 段）与 0x9dxxxxx/0xa0xxxxx 段的卷中继续追。
