# part_000047.c 分析

## 概况

- 函数数：2938（与 profile 一致）；地址域 0x88049a8 – 0x9188620；约 8MB / 200083 行。
- 函数命名良好（GHIDRA 带符号），主要由四大块组成：
  1. **Chaos 物理引擎（最大簇，约 1/3 以上）**：`Chaos::GJKRaycast2<...>` 多个模板实例化、`Chaos::TImplicitObjectScaled/Instanced`、约束构造（ConstructSphereSphereConstraints / ConstructCapsuleConvexConstraints）、BVH `GenerateTree`、`UpdateClusterMassProperties`、`FPBDMinEvolution::IntegrateImpl`、`ComputeIslandColoring`、`FGeometryCollectionPhysicsProxy::Initialize`、`PushToPhysicsStateImp`。对应 top_symbols 里 Chaos 9555 / Freeze 1377。
  2. **移动端渲染器（FMobileSceneRenderer / MobileBasePass 符号 142 个）**：`RenderDeferred`（渲染主序列）、`ConditionalResolveSceneDepth`、`FSceneRenderer::GatherAndSortLights`、`TMobileBasePassPSPolicyParamType::GetShaderBindings`、`BuildMeshDrawCommands` 模板族。
  3. **View uniform 与后处理**：`FViewInfo::SetupUniformBufferParameters`（view uniform 总装配）、`SetupMobileDirectionalLightUniformParameters`、`FPostProcessPassParameters::Set`、`AddGaussianBlurPass`、`DiaphragmDOF::AddPasses`、`FDefaultTemporalUpscaler::AddPasses`(TAA/TSR)、`RenderScreenSpaceDiffuseIndirect`。

  另有 DistanceField/CapsuleShadowing/HairStrands 计算着色器 SetParameters 家族、`FScene::UpdateSceneCaptureContents`、HZB 遮挡任务 `FetchVisibilityForPrimitivesTask::DoTask`。
- **本文件含 7 处 Azure 游戏层扩展痕迹**（全局 `GAzureReplaceLightingParams`、`GAzureIsReplaceShadowCenter`、`GAzureReplaceShadowAutoCalcCenter`、`RenderAzureOutlinePass` 调用），详见"战斗渲染相关性"。无 Spine、无 MID/Sequencer/Lua 相关符号。

## 战斗渲染相关性

**有 3 个直接相关的 Azure 挂点（均已实际读取代码确认）：**

1. **0x8f74ec8 `FMobileSceneRenderer::RenderDeferred`（行 149416-149417）**
   证据：`RenderMobileBasePass(param_1,param_2,param_3,param_4);` 之后立即 `RenderAzureOutlinePass(param_1,param_2,param_3,param_4);`，随后才执行 Occlusion/Decals/MobileDeferredShading。即 **Azure 角色描边 pass 被插在 Mobile BasePass 之后、延迟着色之前每帧调用**。`RenderAzureOutlinePass` 定义不在本文件（全文件仅此一处调用）——它与游戏层 `SetAzureOutlineColor=0xa9040a4` 同属描边系统，是战斗角色描边渲染的每帧入口；找描边参数来源应追该函数定义所在文件。

2. **0x9130678 `FViewInfo::SetupUniformBufferParameters`（行 193300-193318）**
   证据：`if (((char)GAzureReplaceLightingParams == '\0') || (DAT_0c619662 != '\0'))` 时，从调用方结构体偏移 0x15dc–0x1600 区域取两组颜色乘缩放系数（fVar38 = *(param_1+0x15fc)），写入 `FViewUniformShaderParameters + 0x9d0 / + 0x9d8`（第一组 RGB）与 `+ 0x9e0 / + 0x9e8`（第二组 RGB）；否则写 (1,1,1,1)。**+0x9e0 正是已知 AzureIndirectCharacterLightingColorScale per-view uniform 的偏移（0xa3f743c 声明的运行时写入点在本文件）**。行 193323-193335 还有一组 Azure 门控颜色（`+0xe60..+0xe7c`，`GAzureReplaceLightingParams._1_1_` 非 0 时 +0xe7c=1.0）。
   **推断：本函数是"Azure 间接角色光颜色缩放"进入 shader 的引擎端出口；它的上游值在调用方偏移 0x15dc–0x1600 区域（每帧被谁写入不在本文件——写者应在地址更高的分区，即含 0x9dbadd4 SetAzureCharColor / 0xa3e9720 CharacterLightParams 的文件）。追"Value R/G 每帧写"应沿该偏移的写者继续。**

3. **0x8efb15c `SetupMobileDirectionalLightUniformParameters`（行 137790-137808, 137927-137945）**
   证据：`if (GAzureReplaceLightingParams._1_1_ != '\0')` 时，不再读 ULightComponent，而是用全局 `_DAT_0c6196b0` / `uRam0c6196b8` 两组色值 × 0.31830987(1/π) 直接覆写 `FMobileDirectionalLightShaderParameters` 的 DirectionalLightColor（param_10[0..3]）与 BackgroundColor（param_10[4..7]），方向取 `DAT_0c6196c0/0c6196c8` 取负。**Azure 光照替换系统把方向光颜色来源整体换成全局数据区 0x0c6196b0–0x0c6196c8**——这是该替换值的渲染端消费点之一。另 `GAzureIsReplaceShadowCenter`/`GAzureReplaceShadowAutoCalcCenter` 将 CSM 阴影中心偏移放大 ×3.0 / ×2.0 并加 `DAT_0c578ae8`（游戏/渲染线程各一份的全局值）。

**其它全局地址记录**：`GAzureReplaceLightingParams`（标志字节区 ~0x0c619660，`DAT_0c619662` 为第二开关）、颜色数据 0x0c6196b0/0x0c6196b8、方向 0x0c6196c0/0x0c6196c8。这些是 .data/.bss 全局，本文件只读不写（7 处命中全为条件判断/读取）——**写入者（= Azure 替换参数的最终来源）不在本文件**。

**明确排除项**：
- spine 关键词 0 命中；已知 spine 顶点色生产端 0x70b25f0、UMID 族 0xa0e5800、uniform 求值 0xa0fe0a4、MID 落点 0xa10e24c、Sequencer 0x958daa0、Lua VM 0xabd1bb0、SetAzureCharColor 0x9dbadd4 等 anchor 均不在本文件地址域（0x88049a8–0x9188620），且本文件也无对这些地址的 FUN_ 调用引用（逐一 grep 为 0）。
- pulse 12 处命中全部是 Chaos 物理冲量（GetEnergyClampedImpulse / LinearImpulse / ERadialImpulseFalloff 等），与颜色脉冲无关。
- Desaturation / SetVectorParameterValue / CharacterLight 字符串 0 命中（bOverride_AzureCharLightDesaturation 不在本文件）。
