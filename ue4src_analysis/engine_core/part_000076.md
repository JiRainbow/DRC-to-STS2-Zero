## 战斗渲染相关性

**结论：本文件不含战斗角色 Spine 颜色脉冲渲染的实现，但包含该机制必然依赖的材质参数更新通道。** 依据如下：

1. **Spine 运行时：无。** 全文件 `spine` 命中仅 5 处，全部是 `FRadixSortSpineCS`（GPU 基数排序的 "sort spine" 数据结构，CS compute shader + Downsweep/Upsweep + `RadixSortParameterBuffer`，见 0x9fb85c8 / 0x9fb8acc / 0x9fba030）；`spSkeleton|spine::|SkeletonRenderer|SpineTrack` 命中 **0**。Spine 2D 骨骼动画运行时在其它 part。
2. **pulse：非渲染。** 9 处命中为 `FQuartzPulseOverrideStep`（音频 Quartz 音序器反射样板，L189866 起）与 `AddAngularImpulseInRadians`/`AddRadialImpulseToBody`（物理冲量，FBodyInstance）。无任何正弦颜色切换/闪烁逻辑。
3. **颜色脉冲可挂靠的材质参数通道（本文件提供，addr+证据）：**
   - `0xa0e0ffc` UMaterialInstance::SetVectorParameterValueInternal——FLinearColor 写入向量参数数组 + GameThread_UpdateMIParameter 同步渲染线程（贴图色调/颜色参数运行时修改的唯一正规通道之一）
   - `0xa0e5bd0` UMaterialInstanceDynamic::SetScalarParameterByIndex——标量参数（如脉冲强度）直写 + 渲染线程同步
   - `0xa0e55ac` UMaterialInstanceDynamic::Create——战斗中为角色动态创建 MID 的入口
   - `0xa0b8174` FMaterialCachedParameters::FindParameterIndex——按名查参数下标（哈希二分）
   - `0xa12f234` UMaterialParameterCollectionInstance::GetVectorParameterValue、`0xa0e68dc` GameThread_FindAllVectorParameterNames——全局参数集合读写（集合常用于全局脉冲/受击调色）
   - `0xa07f338` ALight::SetLightColor(FLinearColor)
   - UCurveLinearColor / UCurveLinearColorAtlas / FRuntimeCurveLinearColor 反射注册（L147427 起）——曲线驱动颜色动画的基础设施
   - `0xa0e2454` UMaterialInstance::GetEmissiveBoost——自发光增幅参数读取
   - `0xa0dd418`/`0xa0dd444` AzureDepthFade 开关/距离——项目自研材质参数访问器
4. **顶点色：仅基础设施。** `0xa132500` FMeshVertexPainter::PaintVerticesLerpAlongAxis——两 FLinearColor 沿轴插值后 `FLinearColor::ToFColor` 写 FColorVertexBuffer（静态网格刷色工具，非每帧路径）；`0xa86dfcc` UMaterialExpressionVertexColor 类反射注册；`0x9fb3a7c` FGPUBaseSkinVertexFactory::GetColorComponentsSRV——GPU 皮肤顶点色 SRV 暴露（角色网格顶点色进入着色器的通道）；`0xa2a6d0c` GetAggGeom 的 FColor 参数仅为碰撞体调试绘制色。
5. **每帧颜色/脉冲计算不在此文件**：本文件无 per-frame FLinearColor lerp/sin 求值、无 "pure black" 常量切换逻辑；战斗角色颜色脉冲应位于游戏层 part 或渲染线程 mesh batch 组装处（可在其它 part 的 FPrimitiveSceneProxy/FMeshBatch 附近继续追）。
