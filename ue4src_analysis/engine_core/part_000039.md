## 战斗渲染相关性

本文件不含 Spine、MPC（FMaterialParameterCollection）、UMID、SetAzureCharColor(0x9dbadd4)——该地址超出本文件域（0x825981c–0x9062b38），文件内 grep 0x9dbadd4/0xa3e9720/0x95ba2e4/0xa0e5800/0xa12dffc/0x70b25f0 均无命中。但存在一组**Azure 自研引擎渲染钩子（任务高度相关的同类簇）**，逐个列证据：

1. **AzureReplaceDirectionalLight = 0x8eface8 (size 1140)**——最强线索。签名 `(bool, FLinearColor const&, FVector const&)`（函数头注释原文）。渲染线程直接写全局块：
   - `GAzureReplaceLightingParams`（bool 开关，0xc6196b8 区域）
   - `_DAT_0c6196b0`/`uRam...0c6196b8` ← FLinearColor（8 字节 RGBA 打包 + 尾字节）
   - `DAT_0c6196c0`/`DAT_0c6196c8` ← FVector（光方向）
   - 该全局块与任务已知的 `DAT_0c619670`（AzureReplaceMovableIndirectLighting 块）**同属 0xc6196xx Azure 光照替换全局块族**——本文件是"平行光替换"分支的写入端，0xc619670 的写入端（AzureReplaceMovableIndirectLighting）在其它文件，但消费端（BasePass/光照着色器读取这些全局）值得在各渲染文件里追 `0c6196` 前缀引用。**"谁在写 Value R/G"类问题可沿 AzureReplaceDirectionalLight 的调用方（游戏线程侧，bool+FLinearColor+FVector 来源）追查。**
2. **AzureSkipSceneRender = 0x8ed1c40 (976)**——设 GSkipOpaqueRender/GSkipMaskedRender/GSkipAlphaRender；配套收尾任务 0x8f18cd0 恢复 GSkipAlphaRender 并清空 `GAzureNoSkipAlphaProxyNames`（名字白名单，说明 Azure 支持按代理名豁免跳过）。这是"专用来着色 pass 前清空场景"的基建（角色特写/大纲/换装预览常用），与角色渲染强相关。
3. **~FAzureOutlinePassMeshProcessor = 0x8c601a0 / 0x8c601a4 (各 4B)**——Azure 描边 pass 网格处理器的析构残余，紧邻 FAnisotropyMeshProcessor/FBasePassMeshProcessor 析构簇（0x8c600b4-0x8c601ac）。**类主体（构造/GetDynamicMeshElements）在其它文件**；描边 pass 是 Azure 角色渲染体系的一部分。
4. **GEnableAzureDepthFade 全局**——在 **UpdateMobileBasePassMeshSortKeys = 0x8ec1bdc (1832)** 内两处分支（L175100、L175243-175256）：开启时 BasePass 排序键改打包"距离淡出因子"（`distance * 9.536743e-07` 量化后左移 0x35）+ 19bit 代理哈希 + bit62 标记。即 Azure 深度淡出是 BasePass 排序键层面的 per-primitive 特性（远景/水面/角色渐隐类效果），非颜色脉冲本身，但属于 Azure 改造 BasePass 的证据链。
5. **GAzureCheckUpdateFlagsBeforeModify 全局**——Slate 失效门控（0x82598a4 OnTouchEnded L117、0x82a3e64 PrivateAllocateWidget L17585、0x82b5830 SetUseAllottedWidth L19414、0x82bf1a0 SInvalidationPanel L23742）。属 Azure UI 框架钩子，与颜色渲染无直接关系，仅证明 Azure 层在渲染/UI 多处打桩。
6. **疑似 Azure 战斗实体簇：无**。文件内无游戏层实体/战斗系统函数（无 fight/char/actor 伤害类符号），Chaos 物理为引擎自带。FDeferredLightPS::SetParameters(0x8ebbd94)、TDeferredLightOverlapPS(0x8ebb9a0/0x8ebbed8) 是灯光颜色流入着色器的 stock 通道（灯光色经 FLightSceneInfo→uniform），若 AzureReplaceDirectionalLight 的全局块最终被这些 pass 消费即完成"替换平行光颜色"闭环——建议下一步在消费端文件 grep `0c6196b0`/`0c619670` 与 `GAzureReplaceLightingParams`。
7. ILC 相关仅有 stock 函数：IsIndirectLightingCacheAllowed 0x8e5a068、~FIndirectLightingCache 0x8e79b5c、`IndirectLightingCache` uniform 绑定（L178065 等）——未见 Azure ILCShadownessScale 写入端。

**结论**：本文件价值在 0x8ec1000–0x8f19000 的 Azure 渲染钩子簇——尤其 **0x8eface8 是 AzureReplace 光照替换全局块族（含 FLinearColor）的直接写入端**，是"AzureCharColor 值来源/谁写颜色"调查在渲染侧的重要落点；Spine 顶点色/材质参数动画的生产端不在此文件。
