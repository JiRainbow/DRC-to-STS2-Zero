## 战斗渲染相关性
**结论：本卷不含战斗角色 Spine 颜色脉冲链路的任何环节；相关目标地址均不在本卷。**

依据与逐项核查：

1. **0x70b25f0（spine 顶点色生产端）不在本文件**：本卷地址域 0x62c1654–0x6ce0054（profile 与 3787 个 FUNC 标记实测一致），0x70b25f0 高于上界 0x6ce0054；且全文件 grep "spine" 0 命中。无 darkColor RGB787 打包代码可读。附带观察：0x682504c GetTriCoordColorFallback 中存在 8bit+7bit 拼包（`uVar1 = b3 | (b2 & 0x7f) << 8`，15 位索引、0x7fff 哨兵），属 tri-coordinate 索引解码而非颜色打包，仅形似，勿混淆。
2. **0x6e2b57c 不在本文件**（>0x6ce0054，文件内 0 命中）。但 callgraph_edges.csv 给出闭环：`0x6d02438 execReplaceDirectionalLight → 0x6c363e4 ReplaceDirectionalLight`、`0x6e8cf4c FUN_06e8cf4c → 0x6c363e4`；**ReplaceDirectionalLight 函数体在本卷 0x6c363e4（size 60）**。精读（行 200383-200411）：`if (this+0x7f8 非空) { lVar1 = *(this+0x7f8)+0x2a8; *(lVar1+0x311)=param_1(bool); 若开启：param_2 前 4 个 float → lVar1+0x360..0x36f（16 字节），param_3 前 3 个 float → lVar1+0x370..0x37b（12 字节） }`。即目标场景对象偏移 0x7f8 → 内部 0x2a8 处的方向光结构；bool 开关在 +0x311；数组 A=4 float（疑似 RGBA 或 dir+强度），数组 B=3 float（疑似 RGB）。**值来源即 BP 调用 exec thunk 时传入的两个 float 数组，函数体只做转发写，无默认色、无脉冲逻辑。** 另外 callgraph 显示 0x6e2b57c 自身调用了 `0x8eface8 AzureReplaceDirectionalLight`（该地址在其它卷，建议下一卷追查 0x8eface8 与 0x6e8cf4c）。
