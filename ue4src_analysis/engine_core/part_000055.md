## 战斗渲染相关性

**结论：与"贴图原色↔纯黑正弦脉冲"机制直接相关的生产端/值来源函数均不在本卷；本卷只有 Azure 渲染管线的 3 个底座函数，且均为光照替换/描边 pass 的执行端，不是颜色值的产出端。**

**本卷实际拥有的 Azure/战斗渲染边缘函数（3 个，已精读）**：

1. **0x8efc07c (384) `FMobileSceneRenderer::RenderAzureOutlinePass`** — Azure 描边 pass 执行端。证据：函数体内 `FCsvProfiler::BeginExclusiveStat("RenderAzureOutlinePass")`、`UpdateOpaqueBasePassUniformBuffer`、`FParallelMeshDrawCommandPass::DispatchDraw`(pFViewInfo+0x58a0)。它把描边批次以独立 pass 画出来，但**不触碰任何颜色参数**。地址相邻区 0x8efaba8 `CreateMobileBasePassUniformBuffer`(320)、0x8ecd088 `GetMobileBasePassShaders`、0x8eced60 `TryAddMeshBatch`(1768)——整段是 mobile base pass 集群，若追描边 pass 的 shader 排列可从这里顺藤。
2. **0x90b0360 (452) 渲染线程任务（未命名）** — Azure **替换光照参数**的渲染线程写入端：`GAzureReplaceLightingParams`(bool, 全局 0xc6196xx 区) 置位后把 8 个 double（很可能是 2×float4 颜色/方向参数）拷入全局 0xc619670–0xc6196a8。这是"Azure 光照替换"系统的值落点，但值的生产者（game thread 侧打包任务）不在本卷——追 SetAzureCharColor→材质参数链时，这个全局区 0xc619670 是下游消费点，可跨卷 grep `GAzureReplaceLightingParams` / `DAT_0c6196`。
3. **0x8ed0f28 (972) `AzureSkipOpaqueRender(TArray<FString> const&)`** — 调试开关：字符串 "1" → 全局 `GSkipOpaqueRender`，跨线程打包 FGraphTask 到渲染线程。仅用于跳过 opaque 渲染调试，与颜色无关，但证明 Azure 定制渲染路径在本引擎深度侵入 MobileSceneRenderer。

其它颜色相关命中排查：`FLinearColor` 23 处——0x9f9c5e4 地形法线(3 处 FColor→FLinearColor)、0x9dbebd8 DrawBox 调试画线、0x9092eb0 ClearVolumeTextures、0x9f311ec ExternalTexture、USkyAtmosphereComponent::SetRayleighScattering/SetOtherAbsorption、FViewportDisplayDelegate——**全部与角色颜色脉冲无关**。`UMovieSceneMaterialParameterCollectionTrack`（line 130024–130615，仅 UScriptStruct 注册/序列化样板，无求值逻辑）值得留意：若脉冲走材质参数集合+Sequencer，其求值端不在此卷，注册数据在此卷。

**对追"颜色脉冲"的指向**：本卷为否证据——需要转向 0x70b25f0、0x9dbadd4、0x97ee7cc 所在卷；本卷可贡献的只有 0xc619670–0xc6196a8 的 Azure 替换光照全局参数区（消费端）。
