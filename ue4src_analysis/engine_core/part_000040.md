## 战斗渲染相关性

本卷地址域 0x82a526c–0x95683d4 **不覆盖**任何已知锚点：0x6e2b57c（ReplaceDirectionalLight exec thunk）、0x70b25f0（spine 顶点色生产端）、0x9dbadd4（SetAzureCharColor）、0x97ee7cc（FAzureMaterialParamSet::ApplyParams）、0xa0e5800（UMID 参数族）均在区间外；grep `0x6e2b57c|0x70b25f0|0x9dbadd4|0x97ee7cc|0xa0e5800|0x0c6196b0` 全文 0 命中。

但存在 **3 处 Azure 渲染框架接入点**（逐个 addr+证据）：

1. **FAzureOutlinePassVS / FAzureOutlinePassPS（Azure 描边 pass 着色器类）** — 0x8c2cd94(InternalDestroy,40B)、0x8c2cf20(TGetDefaultObjectHelper::Do,8B)、0x8c2cf28(GetTypeLayout,28B)、0x8c2cf44(VS::ConstructSerializedInstance,72B)、0x8c2cfe0(VS::ModifyCompilationEnvironmentImpl,4B)、0x8c2d050(PS::StaticGetTypeLayout,356B)。证据：行144416-144505，PS 类型布局把 `L"AzureOutlineColor"` 注册为 FShaderParameter 字段（行144501-144502），类基座 FMeshMaterialShader（行144508 关联其 StaticGetTypeLayout）。结论：引擎侧存在 Azure 描边 pass，描边颜色以普通 shader 参数（AzureOutlineColor）传入像素着色器——这与角色描边/选中和可能的受击描边表现相关，但本卷只有类型注册/序列化样板，**没有**颜色计算或脉冲逻辑本体。
2. **PipelineStateCache::FlushResources = 0x83ed2c0** 读全局 `GAzureFlushShaderCacheFlag`（行35259-35261）：标志置位时清零并强制刷新图形/计算管线状态缓存。即 Azure 侧代码（在其它卷）可通过置此标志迫使 PSO 缓存整体失效——热重载/运行时改着色器场景有关。
3. **_INIT_500 = 0x84ab954** 内注册 `CmdAzureReleaseCachedShaders` 委托（行61955-61971）：控制台命令 `r.release_cached_shaders`（"Release cached shaders"）的处理委托挂在 Azure 命名对象上，与 #2 同属 Azure 着色器缓存管理面。

专项排查结果：
- ① **0x70b25f0 顶点色填充函数本体不在本文件**（地址低于本卷下界 0x82a526c；grep 零命中），darkColor RGB787 打包逻辑亦无（"787"仅命中无关地址片段，无 darkColor 字符串）。
- ② **本文件内无 0x6e2b57c 的调用者**（常量零命中；且该地址在本卷区间外）。
- ③ **AzureCharColor 值来源在本文件无任何线索**（grep `CharColor`/`SetCharColor` 零命中；本卷 Azure 面仅覆盖描边着色器类型与缓存刷新，不涉及角色颜色参数）。
- Spine/pulse/fight 关键词在 profile 中均为 0，实际 grep 确认；`color` 2278 处全部为引擎通用色彩（FLinearColor/GBlackVolumeTexture/阴影淡化等），与本任务脉冲链无关。战斗渲染链条（SetAzureCharColor→ApplyParams→顶点色）所需函数应在更低（0x6ex/0x70x）或更高（0x97x/0x9dx/0xa0x）地址卷中。
