## 战斗渲染相关性

**结论：本文件不含 Spine 颜色脉冲链路的任何环节，但存在 Azure 光照栈与蒙皮顶点色的边缘函数。**

直接链路核验（全部无命中）：
- `0x6e2b57c`（ReplaceDirectionalLight exec thunk）**未出现**；
- `0x8eface8` / `0x8efb15c` / `0x9130678` / `0x9dbadd4`（SetAzureCharColor）/ `0x97ee7cc`（FAzureMaterialParamSet::ApplyParams）/ `0x0c6196b0`/`0x0c6196b8`（全局）/ `0xa0e5800`（UMID 参数区，超出本文件地址上限 0x9f3d224）均无命中；
- 符号名 `ReplaceDirectionalLight`、`UAzureSceneImage`、`AzureCharColor`、`CustomCharacterTexture`、`SetVectorParameterValue`、`SetScalarParameterValue`、`MaterialInstance` 在本文件 0 命中；keywords：spine=0、pulse=0。

因此 **ReplaceDirectionalLight 的调用方（传蓝色者）与 AzureCharColor/CustomCharacterTexture 的值来源不在本文件**，需到其它 part 追查。

相关但边缘（逐个 addr+证据）：

1. **0x90dba6c `FScene::AzureResetILCData(UPrimitiveComponent*)`** (936)。证据：读体确认——校验 IsInRenderingThread/GGameThreadId 后，游戏线程路径直接调 `FIndirectLightingCache::AzureSetSingleLightingCacheDirty((FIndirectLightingCache*)(this+0x1790), *(param+0x2ec))`；非游戏线程则分配 graph task 投递到 RenderThread 执行。这是 Azure 定制间接光照缓存（ILC）按图元置脏的引擎侧入口，与战斗角色受光（Azure 间接光）同栈，但**不接触颜色/脉冲/材质参数**。
2. **0x9dca86c `UPointLightComponent::SetAzureIntensityScale(float)`** (84)。证据：读体确认——非构造脚本上下文时将 float 写入组件 `this+0x39c`（AzureIntensityScale 字段）。属于"灯组件→角色受色"链路的灯侧标量字段，可视为 0x9dbadd4 SetAzureCharColor 链的**同族邻居**（灯驱动角色着色的 Azure 扩展），但本函数只写强度不写颜色。
3. **0x9e2cb30 `USkinnedMeshComponent::SetVertexColorOverride(int LOD, TArray<FColor> const&)`** (408)。证据：读体确认——释放旧 FColorVertexBuffer 后 `InitFromColorArray`（数量不足按 `FColor::White` 补齐）→ `BeginInitResource` → `MarkRenderStateDirty`。这是蒙皮网格**逐顶点颜色覆盖**的标准引擎 API，是顶点色调制（若战斗闪白/染色走顶点色通道）的合法写入点；但本文件内未发现它的调用方。
4. **0x9e2c9b8 `FSkelMeshComponentLODInfo::ReleaseOverrideVertexColorsAndBlock()`** (72)。证据：读体确认——`BeginReleaseResource(+0x10 的 FRenderResource)` + `FlushRenderingCommands` + 删除，是 #3 的释放对偶。
5. **0x90ea750 `FScene::DumpUnbuiltLightInteractions`** (2568)。证据：读头确认遍历 FLightSceneInfo 转储未建交互，仅调试，无颜色逻辑。
