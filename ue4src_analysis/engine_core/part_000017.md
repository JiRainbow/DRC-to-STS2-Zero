## 战斗渲染相关性
本卷虽是底座卷，但**命中任务特别目标 ①**，并有一条顶点色生产链证据：

1. **0x70c0d30（顶点色填充调度器，312B）——0x70b25f0 在库内的直接调用方**（证据：line 23914 `FUN_070b25f0(*(undefined4 *)param_1[4], uVar5, pbVar6, ...)`）。关于任务假设"0x70b25f0 落在函数表空洞=内联"：本卷中 0x70b25f0 确实无 FUNC 头（位于 FUN_070b0bc4 与 FUN_070b36e4 之间的 0x29c8 字节空洞），**但它在本卷是作为被调用函数出现的**（非内联体），其函数体定义在 part_000009.c / part_000001.c 侧（grep 确认两文件含该符号）。即 0x70b25f0 是独立函数，只是函数头被切到了其它分卷；"内联于更大函数体"的说法不成立，应改为"定义体在其它分卷"。
   - 分流逻辑：slot 标志 bit1=0 → FUN_070b2424（定义体同样在外部卷，本卷仅 1 处调用 line 23910）；bit1=1 → FUN_070b25f0。两条路径输出参数布局完全一致（6 个输出色指针），即同一 Spine 顶点结构的 **Color + Dark（二级 tint）** 两套 RGBA。第一参 `param_1[4]` 是上下文里的一个颜色/色值来源字段——与 AzureCharColor 值来源的关联值得在 part_000009.c 反查 FUN_070c0d30 调用者（part_000003.c 亦引用 FUN_070c0d30）。
2. **0x70b82a4（Spine 默认材质族加载，892B）**：缓存 4 个全局材质（DAT_0c37da50=游戏自定义 MySpineLitNormalMaterial、da58=Additive、da60=Multiply、da68=Screen）。Spine 角色换材质/换混合模式的底座，材质参数动画（UMID 族）若作用于这些实例，会经此路径。注意 `/Game/ParentMaterials/MaterialMasters/SpineMaterials/` 是项目自己的 Spine 母材质目录——追 SetAzureCharColor(0x9dbadd4) 参数落点时可对照该母材质的参数名。
3. **0x70a0240（__spine-ue3_custom_skin 皮肤注入，672B）**：运行时为 Spine 骨骼挂自定义皮肤，换装/换色皮肤机制一环。
4. **0x70b415c（slot 位图状态更新，792B）**：Spine 骨骼 slot 剔除/重建，渲染数据维护侧。
5. **0x70037b4（ClearVertexColorOverride BP thunk，236B）**：引擎 SkinnedMeshComponent 顶点色覆盖清除 API 的蓝图入口——顶点色覆盖机制存在引擎级支持，战斗角色若走 USkinnedMeshComponent 路线会用到；Spine 路线则不走此处。
6. **0x7231a70（FPaperRenderSceneProxy_SpriteBase::SetSprite_RenderThread，560B）**：Paper2D 精灵渲染线程顶点重建（FDynamicMeshVertex 含顶点色）。2D 渲染同族，但非 Spine/Azure 链。
7. **顶点色生成链小结（本卷内）**：part_000003.c 调 0x70c0d30 → 0x70c0d30 按槽标志分流 → 0x70b25f0（顶点色+二级色生产，体外定义）。0x70b25f0 的上游证据链：spine 顶点色生产端=0x70b25f0 已确认（前卷结论），本卷补上它的**调用上下文**（0x70c0d30 输出缓冲 0x78 步长、6 组色指针）。
8. **否定性结论（均有 grep 依据）**：
