# 龙族 → 杀戮尖塔 2 mod 工程迁移说明

> 生成：2026-10-09。配套文件：`manifest.json`（机读清单）、`transfer.py`（复制/校验工具）、`repack_pck.py`（无 Godot 重打包）。
> 本目录内容清单中的仓库已按"必要/高价值/可弃"分级，T1 为推荐最小迁移集。

## 0. TL;DR

```bat
:: 在源机（本目录下）——复制 T1 必需集（≈7.6G）到目标盘
python transfer.py --copy E:\drc-sts2 --tier 1

:: 目标机上校验拷贝完整性（含三份最终产物 sha256）
python transfer.py --verify-dest E:\drc-sts2 --tier 1

:: 源机上随时校验 manifest 全路径与产物指纹
python transfer.py --verify --tier 3
```

复制走 `shutil.copytree`（无外部进程依赖），已在源机实测拷贝+目标端校验闭环通过。

## 7. 就地瘦身（2026-10-09 执行）

把 `D:\项目\dragonraja` 原地瘦身为 T1 保留集，完整旧树改名为 `dragonraja2` 作伪删除备份：

```
D:\项目\dragonraja    = 瘦身树（T1，≈9.9G：含 resources 2.3G + ingameupdate 5.5G）
D:\项目\dragonraja2   = 瘦身前完整树（T2 研究库/T3 残留都在这——unpacked/reversed、
                         res_*全集、render_work 实验目录、apk 解压、iguf 中间物……）
```

**执行方式（已做成自动闭环）**：改名时 ZCode 会话进程占用着 `dragonraja` 目录
（Windows 不允许改被占用目录的名，WinError 32），因此改名动作交给计划任务
**DRCSwap**（每分钟一次；执行体 = 稳定入口 `D:\项目\drc_swap.cmd`，它再调用双树内
任一 `_migration\finish_swap.py`。入口放在两棵树之外，保证 cmd 自身不会持有被改名
目录内的文件句柄——否则第二次改名必定失败死循环）：

- ZCode 完全退出后 ≤1 分钟自动完成：`dragonraja→dragonraja2`、`dragonraja3→dragonraja`，
  并对新树重跑 toolchain_check 出报告 `_migration\swap_report.txt`；
- 完成后任务自删（`drc_swap.cmd` + `finish_swap.py` 幂等状态机双保险；重复触发安全）；
- 也可不等 ZCode：关掉 ZCode 后双击 **`D:\项目\drc_swap.cmd`** 立即执行；
- 进度随时看 `<活树>\_migration\_swap_status.txt`（state=locked 表示还在被占用等待）。

**验收**：`python _migration\toolchain_check.py`（默认root=树根）应 FAIL=0；唯一允许的
WARN 是"T2/T3 未随迁"（ue4_dump/lua_build_index/verify_ue4src/dump_lua_regtable 四个
引用 unpacked/reversed 与 so，其数据在 dragonraja2 里，需要时从那边调）。
已实测：T1 拷入 dragonraja3 后全量 sha256 对拷校验 0 差异（14,847 + resources 2,500 文件），
工具链自检 FAIL=0。

**回退**：万一瘦身树有问题——把 `dragonraja2` 改回 `dragonraja` 即可（重命名即可逆）。
确认长期无恙后，`dragonraja2` 可整体删除（其中 T2/T3 都有再生成路径，见 §2/§4）。
